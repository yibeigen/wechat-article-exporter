## 一、逆向攻击手法深度剖析（知己知彼）

普通 Electron 桌面应用如果不做防护，极易被懂技术的攻击者通过以下 3 步破解：

```
[未经防护的 exe] 
       │
       ▼ (1) 使用 asar 工具解包
[提取 app.asar 源码目录]
       │
       ▼ (2) VS Code 全局搜索 "1588" 或 "app_activated"
[找到鉴权函数并直接修改为 return true]
       │
       ▼ (3) 重新 asar pack 打包
[软件被破解并改名为他人作品]
```

### 攻击者常用手段：
1. **Asar 提取**：使用 `npx @electron/asar extract app.asar ./src` 即可还原出所有明文 JS、HTML 和 CSS。
2. **AI 代码分析**：如果只是普通压缩（minify），攻击者将代码丢给 AI（Claude/ChatGPT），AI 会根据上下文还原逻辑。
3. **明文凭据搜索**：直接搜索关键字（如 `1588`、`app_activated`、`isActivated`）并修改分支。

## 二、分发格式建议：安装版 (.exe) vs 便携版 (.zip)

在软件分发时，**强烈建议同时提供以下两种格式**（工号三刀等成熟工具均采用此标准）：

| 分发格式 | 文件命名示例 | 适用人群与优势 |
| :--- | :--- | :--- |
| **1. 绿色便携免安装版** | `BlogDistiller-v1.0.0-win-portable.zip` | 🌟 **强烈推荐**！解压即用、不写系统注册表、无需管理员权限。适合公司受限电脑、网吧及小白用户。 |
| **2. 一键独立安装包** | `BlogDistiller-Setup-v1.0.0.exe` | 适合电脑基础弱的用户，自动在桌面和开始菜单创建快捷方式，支持一键卸载。 |

> 💡 **小贴士**：使用 `electron-builder` 打包时，**一条指令即可在 1 分钟内同时产出这两种格式**，无需维护两套代码！

## 三、三大工业级防逆向与代码加固体系

```
                       ┌───────────────────────────────┐
                       │   原始干净源代码 (开发者本地)   │
                       └───────────────┬───────────────┘
                                       │ 仅在执行打包时临时加固
                                       ▼
 ┌───────────────────────────────────────────────────────────────────────────┐
 │ 【第一道防线】JavaScript-Obfuscator 深度混淆                                │
 │  - 控制流扁平化 (Control Flow Flattening): 将函数拆为虚拟状态机，打碎逻辑     │
 │  - 字符串十六进制数组加密 + 动态自解密                                       │
 │  - 死代码与虚假分支注入                                                    │
 └─────────────────────────────────────┬─────────────────────────────────────┘
                                       │
                                       ▼
 ┌───────────────────────────────────────────────────────────────────────────┐
 │ 【第二道防线】Bytenode V8 机器字节码编译 (.jsc)                              │
 │  - 将主进程逻辑直接编译为底层机器二进制操作码                               │
 │  - 软件包中彻底不包含任何 JavaScript 代码文本                                │
 │  - AI 和反编译器看到的是纯二进制指令，无法还原业务源码                        │
 └─────────────────────────────────────┬─────────────────────────────────────┘
                                       │
                                       ▼
 ┌───────────────────────────────────────────────────────────────────────────┐
 │ 【第三道防线】Electron-Builder 生产环境封锁                                 │
 │  - 关闭 DevTools 调试通道，禁用热键 F12                                    │
 │  - nodeIntegration: false + contextIsolation: true 隔离渲染层              │
 │  - 输出 Setup.exe 与 Portable.zip                                         │
 └───────────────────────────────────────────────────────────────────────────┘
```

### 1. 第一道防线：AST 深度代码混淆与字符串动态加密

使用 `javascript-obfuscator` 对关键鉴权代码进行高强度混淆配置：

```javascript
// obfuscator.config.js
module.exports = {
    compact: true,
    controlFlowFlattening: true,             // 控制流扁平化（彻底打散 if/else 逻辑）
    controlFlowFlatteningThreshold: 0.8,
    deadCodeInjection: true,                 // 注入大量虚假无用代码混淆视听
    deadCodeInjectionThreshold: 0.5,
    stringArray: true,                       // 字符串全部提取到外部数组
    stringArrayEncoding: ['base64', 'rc4'],  // 双重加密字符串（包括密钥、接口地址）
    stringArrayThreshold: 0.9,
    splitStrings: true,                      // 将长字符串切碎拼接
    identifierNamesGenerator: 'hexadecimal', // 所有变量名全部转为十六进制乱码 (_0x5a1b)
    disableConsoleOutput: true,              // 生产环境禁用 console.log 输出
};
```

### 2. 第二道防线：V8 原生机器字节码编译 (Bytenode)

`Bytenode` 是目前保护 Node.js / Electron 商业机密最顶级的免逆向方案：

- **原理**：直接调用 Node 底层 V8 引擎的 `ScriptCompiler::CompileUnboundScript` API，把 `.js` 源码预先编译为 **V8 原生机器字节码（`.jsc` 文件）**；
- **效果**：
  - 运行时 Electron 直接执行 `.jsc` 二进制；
  - 攻击者即便解包出 `.jsc`，得到的也是一堆十六进制字节流（`0x28 0x9f 0x01...`），**完全无法被 AI 或常规反编译器还原**！

### 3. 第三道防线：Electron 生产安全隔离与防调试

在 `desktop/main.js` 中固化生产安全策略：

```javascript
// 1. 禁用生产环境快捷键打开开发者工具
if (app.isPackaged) {
    mainWindow.webContents.on('devtools-opened', () => {
        mainWindow.webContents.closeDevTools();
    });
}

// 2. 严格隔离渲染进程
const mainWindow = new BrowserWindow({
    webPreferences: {
        preload: path.join(__dirname, "preload.js"),
        nodeIntegration: false,    // 严禁渲染进程直接执行 Node
        contextIsolation: true,    // 强制上下文隔离
        enableRemoteModule: false
    }
});
```

## 四、一键自动化打包流水线实操

### 1. 安装打包与加固工具（仅需安装一次）

在项目根目录下运行：
```powershell
npm install --save-dev electron-builder javascript-obfuscator bytenode
```

### 2. 打包配置文件 (`desktop/package.json`)

在 `desktop/package.json` 中配置 `build` 选项：

```json
{
  "name": "blogdistiller-desktop",
  "productName": "BlogDistiller 微信文章导出助手",
  "version": "1.0.0",
  "main": "main.js",
  "scripts": {
    "start": "electron .",
    "dist": "electron-builder --win"
  },
  "build": {
    "appId": "com.yibeigen.blogdistiller",
    "productName": "BlogDistiller 微信文章导出助手",
    "copyright": "Copyright © 2026 艺杯羹",
    "directories": {
      "output": "../dist"
    },
    "win": {
      "icon": "renderer/assets/logo_icon.png",
      "target": [
        {
          "target": "nsis",
          "arch": ["x64"]
        },
        {
          "target": "zip",
          "arch": ["x64"]
        }
      ]
    },
    "nsis": {
      "oneClick": false,
      "allowToChangeInstallationDirectory": true,
      "createDesktopShortcut": true,
      "createStartMenuShortcut": true,
      "shortcutName": "BlogDistiller 微信文章导出助手"
    }
  }
}
```

### 3. 一键打包命令

在 Windows 终端中运行：
```powershell
# 一键生成 Setup.exe 安装包与 Portable.zip 便携包
npm run dist
```
打包完成后，产物会自动生成在 `dist/` 目录下：
- 📦 `BlogDistiller 微信文章导出助手 Setup 1.0.0.exe`（安装版）
- 🗂️ `BlogDistiller 微信文章导出助手-1.0.0-win.zip`（便携免安装版）

## 五、常见问题与避坑指南

### Q1：加固混淆后，我自己修改代码会受影响吗？
> **答：绝对不会！**  
> 您电脑里的源代码永远是原汁原味、结构清晰的。混淆加固过程只发生在执行打包命令的临时内存和产物中，您的源代码永远保留完好。

### Q2：为什么有些杀毒软件（360 / Windows Defender）会误报？
> **答**：所有没有花几千元购买微软官方数字签名证书（EV Code Signing）的开源/独立开发软件，首次在其他电脑运行时都有可能触发 Windows SmartScreen 提示“未知发布者”。  
> **应对策略**：
> 1. 在公众号/下载页写明：*“提示未知发布者时，点击【更多信息】➔【仍要运行】即可，本软件纯净开源，承诺无毒无后台！”*；
> 2. 提供绿色免安装 ZIP 包，ZIP 压缩包的误报率远低于 setup 安装包。

### Q3：老用户升级后，之前输入的激活码还会有效吗？
> **答：永久有效！**  
> 激活凭证保存在用户的系统数据目录中（`DATA_DIR` 与 `localStorage`），即使覆盖安装新版本软件，已激活状态依然终身保留，老用户无需重复输入！
