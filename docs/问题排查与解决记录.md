## [2026-08-20 16:30] 🛠️ 多平台富文本抓取与 HTML 转换 DOCX 排版混乱失真

- **应用场景/所属模块**：`backend/app/parsers/` & `desktop/main.js` (富文本转换引擎)
- **问题分类**：`数据解析缺陷` / `文档排版`

### 1. 遇到什么事 (现象与现场)
- **现象描述**：从知乎、微信等平台抓取的原始 HTML 包含大量私有 CSS 变量、内联 SVG 图标、公式及广告标签。直接使用通用 HTML-to-Docx 工具转换时，遇到未知标签抛出异常中断，生成出来的 Word 文档段落黏连、字阶错乱。
- **关键报错/日志**：
  ```text
  Unsupported tag <section data-role="outer"> during HTML parsing; Paragraph hierarchy malformed.
  ```

### 2. 怎么解决的 (排错历程与最终解法)
- **踩坑历程（无效尝试）**：
  1. *尝试一*：直接正则表达式粗暴替换 HTML 标签，导致嵌套代码块和有序列表缩进丢失。
  2. *尝试二*：直接写入原生 HTML 到 DOCX 容器，在各版本 Office 下兼容性极差。
- **最终解法**：
  1. 引入 Linkedom + Turndown 构建**语义清洗与降维管道**；
  2. 先行剔除广告节点、无意义样式容器（`data-role`, `powered-by`）；
  3. 将清洗后的 DOM 树标准化降维为 Markdown AST；
  4. 自研定制 DOCX 渲染构建器，将 Markdown AST 映射为标准的各级 Heading、CodeBlock、Quote 和 Table 结构。
- **关键改动 (Diff / 关键逻辑)**：
  ```javascript
  // 语义降维管道：HTML -> Clean DOM -> Markdown AST -> Native Docx Paragraphs
  const cleanHtml = sanitizeHtmlTree(rawHtml, { stripAds: true, keepFormulas: true });
  const markdownAst = turndownService.turndown(cleanHtml);
  const docxParagraphs = renderMarkdownAstToDocx(markdownAst);
  ```
- **验证结果**：知乎和微信长文成功转换为结构严整的 DOCX，代码块带浅灰背景，引用块带左边框。

### 3. 即时经验
- 跨平台富文本导出严禁直接拿原始 HTML 硬转；必须先进行“语义降维（HTML -> Clean AST）”，再基于目标文档对象模型进行“自顶向下重建”。

## [2026-08-25 21:50] 🛠️ 微信头像与封面图片跨域 403 Forbidden 裂图

- **应用场景/所属模块**：`frontend/wechat.html` & `desktop/renderer/index.html` (图片渲染)
- **问题分类**：`防盗链策略` / `静态资源加载`

### 1. 遇到什么事 (现象与现场)
- **现象描述**：抓取公众号列表后，公众号圆形头像以及文章封面缩略图在界面上全部显示为浏览器默认的破损图片图标。
- **关键报错/日志**：
  ```text
  GET https://mmbiz.qpic.cn/mmbiz_png/... 403 (Forbidden)
  ```

### 2. 怎么解决的 (排错历程与最终解法)
- **踩坑历程与根因剖析**：
  微信图片 CDN（`mmbiz.qpic.cn`）启用了严格的 Referrer 防盗链校验。当浏览器从本地 `file://` 或非白名单域名发起图片请求时，带上了宿主 Referrer，被微信服务器直接拒收 403。
- **最终解法**：
  1. 在前端 HTML `<head>` 中注入全局策略：`<meta name="referrer" content="no-referrer">`；
  2. 对于导出本地文档的场景，在后端通过纯 Python `httpx` 发起带自定义 Header 的图片拉取并落盘为本地缓存，切断浏览器端的网络依赖。
- **关键改动 (Diff)**：
  ```diff
  + <meta name="referrer" content="no-referrer">
  ```
- **验证结果**：所有公众号头像、文章封面及正文配图 100% 正常高清渲染。

### 3. 即时经验
- 凡是处理微信等主流平台的图片资源，前端页面必须声明 `no-referrer`，导出文档必须走后端本地缓存管道。

## [2026-08-28 15:40] 🛠️ 微信凭证 30 分钟自然过期 (`ret: -3`) 缺乏透明化提示导致“以为坏了”

- **应用场景/所属模块**：`backend/app/core/wechat_auth.py` & `desktop/renderer/index.html`
- **问题分类**：`风控机制透明化` / `用户体验`

### 1. 遇到什么事 (现象与现场)
- **现象描述**：用户首次抓取成功后，半小时后再次点击抓取提示“抓取失败”，用户不知道需要等待多久，误以为程序彻底失效。
- **关键问题根因**：微信客户端下发的 `key` 默认仅有 1800 秒（30分钟）生命周期，过期后微信返回 `ret: -3`。程序未对凭证倒计时进行可视化监控。

### 2. 怎么解决的 (排错历程与最终解法)
- **最终解法**：
  1. 建立**微信风控三级诊断体系**（`ret: -3` 凭证过期 ➔ 0秒微信点开即恢复；`ret: -6` 短时限频 ➔ 自动退避重试；单日重度风控 ➔ 切换微信小号0秒绕过）；
  2. 在界面常驻凭证生命周期倒计时（如 `29:59`），过期时弹出醒目的一键恢复指引。
- **验证结果**：用户能够清清楚楚掌握凭证状态，极大减少了误判与困惑。

## [2026-08-28 20:30] 🛠️ Word 文档 (.docx) 导出配图缺失与纯文本占位符问题

- **应用场景/所属模块**：`desktop/main.js` (Word 导出引擎) / `docx` 渲染器
- **问题分类**：`功能缺陷` / `用户体验`

### 1. 遇到什么事 (现象与现场)
- **现象描述**：导出的 Word 文档中，图片显示为 `[配图: 图片]` 的文字占位符，提示用户去网上搜。
- **关键问题根因**：生成 Docx 时仅将 Markdown 文本写入 Paragraph，未读取本地已下载的图片二进制 Buffer 并调用 `docx.ImageRun` 插入。

### 2. 怎么解决的 (排错历程与最终解法)
- **最终解法**：
  1. 引入 `image-size` 与 `docx.ImageRun`；
  2. 真实读取本地磁盘 `images/` 中的图片二进制文件；
  3. 识别图片原始宽高，按版心最大宽度（500px）等比缩放并居中插入；
  4. 补齐封面大页、标题映射、代码块背景与引用段落。
- **关键改动 (Diff / 关键代码)**：
  ```javascript
  const dimensions = imageSize(imageBuffer);
  const maxWidth = 500;
  let finalWidth = dimensions.width || 400;
  let finalHeight = dimensions.height || 300;
  if (finalWidth > maxWidth) {
      finalHeight = Math.round((finalHeight * maxWidth) / finalWidth);
      finalWidth = maxWidth;
  }
  paragraphs.push(new docx.Paragraph({
      alignment: docx.AlignmentType.CENTER,
      children: [new docx.ImageRun({ data: imageBuffer, transformation: { width: finalWidth, height: finalHeight } })],
      spacing: { before: 120, after: 120 }
  }));
  ```
- **验证结果**：Word 文档在 Word/WPS 中均完美呈现高清真实图片与精美排版。

- **应用场景/所属模块**：`backend/app/scrapers/csdn.py` (CSDN 爬虫引擎)
- **问题分类**：`运行时依赖缺失` / `网络连接重试`

### 1. 遇到什么事 (现象与现场)
- **现象描述**：用户输入博主主页（实际发布有 122 篇文章），但系统仅能提取出 88 篇或中断在第 1 页（20篇）。
- **关键报错/日志**：
  ```text
  NameError: name 'asyncio' is not defined at line 122 (await asyncio.sleep(0.15))
  httpcore.ConnectError / Server disconnected without sending a response
  ```

### 2. 怎么解决的 (排错历程与根因剖析)
- **根因剖析 (5-Whys)**：
  1. `csdn.py` 顶层缺失 `import asyncio`，导致第 1 页抓取完执行 `await asyncio.sleep(0.15)` 时直接触发 `NameError`；
  2. 外层 `try...except` 捕获了该异常并打印日志退出，使抓取静默中断在第 1 页；
  3. CSDN 官方 API 在多页高频连续请求时，边缘 CDN 偶发主动断开 Keep-Alive 连接，若没有单页重试机制会导致多页循环提前终止。
- **最终解法**：
  1. 补齐 `import asyncio`；
  2. 在分页 `client.get` 请求外层增加 3 次自动重试与自适应退避；
  3. 优化分页循环边界条件，严格比对 `total_expected`。
- **验证结果**：博主 `qq_46987323` 全部 122 篇历史文章 100% 完整提取成功。

### 3. 即时经验
- 异步分页爬虫在每次请求与休眠前必须确保模块依赖完整；长链路分页必须为单个页码的请求封装 3 次幂等重试，防止偶发连接重置断裂整个抓取链条。
