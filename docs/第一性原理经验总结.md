## 🧭 一、 第一性原理本质剖析 (First-Principles Insights)

### 1. 跨平台富文本与文档密封性原理 (Document Engine & Asset Solidification)
- **表面现象**：抓取 HTML 转 Word/PDF 样式崩塌、图片裂开、文字占位符。
- **第一性原理剖析**：
  - 各内容平台（微信/知乎）的 HTML 包含大量私有渲染上下文（CSS Houdini、行内变量、动态计算的高度）。直接硬转必然破坏文档流。
  - 文档文件（`.docx` / `.pdf` / `.html`）本质上是**静态密封的数据容器（Sealed Data Container）**。脱离生成环境后，任何基于远程 URL 的引用都会因**网络隔离、防盗链拦截或凭证过期**而发生不可逆的“断链”。
- **底层元原则 (Meta-Rules)**：
  1. **语义降维法则**：富文本跨格式转换必须遵循 `Raw HTML -> Clean DOM -> Canonical Markdown AST -> Target Document` 的语义降维管道，先剔除噪音再按目标文档对象模型（DOM/OpenXML）重建。
  2. **二进制固化法则**：内容导出前必须将所有外链图片与多媒体数据固化为本地二进制 Buffer，并在插入时显式施加版心宽度守卫与比例锁。

---

### 2. 爬虫与第三方协议对抗第一性原理 (Crawler Protocol & Anti-Risk Invariance)
- **表面现象**：公众平台创作者后台搜号接口被封杀、微信阅读凭证过期返回 `ret: -3` 或频控 `ret: -6`。
- **第一性原理剖析**：
  - 平台的反爬本质上是**“识别异常行为特征”与“剥夺特权接口”的过程**。官方创作者后台属于中心化特权接口，封禁成本极低；而客户端点开文章所走的是**海量真实终端的日常基线流量**。
  - 防封控的核心不是“破解微信加密算法”，而是**“将程序行为完全伪装成真实用户的阅读流量”**。
- **底层元原则 (Meta-Rules)**：
  1. **去特权化法则**：放弃不可控的中心化后台接口，全面采用“本地 PAC 代理 + 真实客户端流量嗅探”技术路线。
  2. **风控透明化法则**：系统必须建立精细的风控三级诊断体系（自然过期 ➔ 0秒微信点开续期；短时限频 ➔ 指数退避；重度风控 ➔ 切换小号0秒绕过），彻底消除用户的黑盒焦虑。
  3. **数据本地沉淀法则**：历史数据一旦拉取成功，必须立即做本地缓存持久化，后续查看与导出 100% 走本地磁盘，实现 0 网络风控。

---

### 3. WAF 攻防对抗与特权通道对冲原理 (WAF Defense & SEO Privilege Invariance)
- **表面现象**：51CTO 在本地 Windows 可正常抓取，但部署到云服务器（Linux 数据中心 IP）后返回 567 质询拦截，检索文章数为 0。
- **第一性原理剖析**：
  - 云安全 WAF（如腾讯云 EdgeOne、Cloudflare）会依据 IP 信誉库对机房/云主机 IP 施加最高强度的防御规则（强制执行动态 JavaScript PoW 算力挑战）。Linux 无头 Chromium 因缺失真实硬件渲染上下文（WebGL、插件指纹）无法通过该挑战。
  - **内容型商业网站存在商业悖论**：网站必须依赖公网搜索引擎（Google、Baidu、Bing）收录以获取 SEO 流量，因此 WAF 防火墙底层必然对合法的搜索引擎爬虫配置了**无阻断放行通道（SEO Bypass）**。
- **底层元原则 (Meta-Rules)**：
  1. **特权通道对冲法则**：当遭遇针对机房 IP 的重度前端 JS 挑战阻断时，优先探测并对齐平台为 SEO 开放的公开抓取通道（SearchBot 协议），以极小算力代价获取完整 HTML 数据。
  2. **多通道异构容灾法则**：爬虫引擎必须设计为“秒级特权通道 ➔ 真实无头浏览器渲染”的多通道自愈兜底架构，兼顾极端穿透率与极速响应。

---

### 4. 异步网络 I/O 幂等与断线重试不变量 (Async I/O Idempotency & Connection Recovery)
- **表面现象**：CSDN 122 篇博文只拉取到 88 篇即中断；代码中缺失 `import asyncio` 导致静默失败。
- **第一性原理剖析**：
  - 长链路多页分页 I/O 属于分布式高频请求，边缘网关在高频访问下有概率主动断开 Keep-Alive 连接（`Server disconnected without sending a response`）。
  - 若单步请求缺失局部容灾与重试，单点网络抖动将引发整个分页管道的雪崩式中断。
- **底层元原则 (Meta-Rules)**：
  1. **单页粒度幂等重试法则**：长链路分页必须为单个页码封装 3 次自动重试与自适应退避机制，将单点网络抖动的破坏半径隔离在单页内部。
  2. **依赖强校验法则**：异步分页控制流中调用的所有模块（如 `asyncio`）必须在顶层显式声明并经过静态检查。

---

### 5. 解释型运行时与单点故障扩散 (Runtime Scope & Failure Blast Radius)
- **表面现象**：`background.js` 中一个未闭合的监听器或全局作用域重名变量导致整个浏览器扩展或客户端全部按钮无响应。
- **第一性原理剖析**：
  - JavaScript V8 引擎在执行前会先进行**全脚本预编译（Parse & Compile Phase）**。
  - 顶层作用域下的语法错误（`SyntaxError`）会在预编译阶段直接终止整个脚本的执行，其破坏半径是**整个执行上下文（Execution Context / Service Worker）的直接死亡**。
- **底层元原则 (Meta-Rules)**：
  1. **命名空间绝对收敛**：严禁在全局作用域下平铺声明通用函数，所有运行时方法必须统一挂载在受控命名空间（如 `window.AppCore`）下。
  2. **静态门禁法则**：任何前端与扩展代码交付前，必须无条件通过 `node --check` 自动化语法门禁。

---

### 6. 桌面应用视口锁死与边界约束 (Desktop Viewport & Layout Invariance)
- **表面现象**：最右侧出现全局双滚动条、右下角空白溢出。
- **第一性原理剖析**：
  - 桌面软件（Electron）的物理边界是绝对固定的操作系统窗口边界。
  - 当根容器允许全局滚动时，任何子组件的 margin 溢出都会导致全屏滚动条产生，破坏“原生桌面应用的质感”。
- **底层元原则 (Meta-Rules)**：
  1. **视口锁死法则**：桌面应用根节点必须强行锁死：`html, body { height: 100vh; overflow: hidden; }`。
  2. **滚动权限代理法则**：全屏滚动权限只能严格下放到具体的数据容器内部（如 `.article-table-wrapper`），禁止向外溢出。

---

### 7. 跨平台二进制传输与管道流式 I/O (Binary I/O & Streaming Transport)
- **表面现象**：Windows 终端 Emoji 输出报 GBK 编码错误、100MB+ 安装包上传至 GitHub 时连接中断。
- **第一性原理剖析**：
  - 操作系统终端具有区域编码依赖性（Windows 中文默认为 CP936/GBK），未声明编码的标准输出在遇到 Unicode 宽字符时必然抛出 `UnicodeEncodeError`。
  - 大体积二进制文件（>100MB）如果采用全量内存缓冲（In-Memory Buffer），会迅速耗尽堆内存并在弱网环境下发生连接超时。
- **底层元原则 (Meta-Rules)**：
  1. 跨平台脚本必须在入口处强制重构标准 I/O 为 `utf-8`。
  2. 二进制大文件分发必须采用**底层的流式分块传输（Streaming Pipeline）**或调用操作系统原生网络工具（如 `curl.exe`）。

## 🤖 二、 可直接提供给其他 AI 的 Prompt / Rules 规范库 (Ready-to-Use AI Rules)

> [!TIP]
> **使用方式**：直接复制下方代码块中的内容，粘贴至项目的 `AGENTS.md`、`.cursorrules` 或作为 Prompt 发送给任何 AI（Cursor / TraeCode / Antigravity / Claude / ChatGPT）。

```markdown
# 项目专属协作与编码规则 (AI Prompt & Coding Guidelines)

## 1. 文档导出与富文本渲染引擎
- 【语义降维管道】：跨平台富文本（HTML）转换严禁直接硬转，必须遵循 HTML -> DOM清洗 -> Markdown AST -> 目标文档 的降维重建流。
- 【资产固化原则】：所有导出格式（Word/PDF/HTML）必须真实读取本地已缓存的二进制图片（Buffer），禁止仅插入远程 URL 或文字占位符；必须读取原始尺寸并按版心等比缩放居中。
- 【Referrer 防盗链】：前端涉及微信等平台图片展示时，必须声明 <meta name="referrer" content="no-referrer">；导出场景必须走后端本地磁盘缓存通道。

## 2. 爬虫协议与反风控安全
- 【去特权化嗅探】：微信公众号历史文章抓取严禁依赖官方创作者后台草稿箱接口，统一采用“本地 PAC 代理嗅探 + 专属主页直达链接（profile_ext）”架构。
- 【WAF 特权通道】：当目标平台（如 51CTO/CDN）对云服务器机房 IP 实施严格 JS 质询（HTTP 567）时，优先配置合法的 SearchBot 特权请求头以穿透防护，并以 Playwright Stealth 作为异构兜底。
- 【长链路分页容灾】：长链路分页必须为单个页码的 HTTP 请求封装 3 次自动重试与指数退避，确保网络抖动不中断全量抓取。
- 【零风控本地沉淀】：推文与抓取结果必须第一时间落盘至 ~/.blogdistiller_data/cache/，前端切换与导出 100% 读取本地磁盘缓存，杜绝重复网络请求触发单日封禁。
- 【风控透明化】：实时计算并透传凭证 30 分钟倒计时，提供清晰的 0 秒小号切换与点开即续期指引。

## 3. 前端桌面布局与脚本安全
- 【单页视口锁死】：桌面客户端（Electron）根容器必须严格声明 html, body { height: 100vh; overflow: hidden; }，仅允许在数据表格区域内部开启 overflow-y: auto，杜绝全局双滚动条。
- 【命名空间隔离】：禁止在前端全局作用域下随意使用 const/function 声明通用变量（如 copyText），统一通过 AppUtils 或 window.blogDistiller 注入，避免编译期 SyntaxError 导致全站白屏。
- 【语法必检规则】：每次对大型单文件 HTML/JS 及扩展 background.js 进行修改后，必须主动执行静态语法校验（node --check 或解析器验证）。

## 4. 后端服务与跨平台构建
- 【注解依赖完整】：在 FastAPI/Flask 新增路由时，若使用 Query / Body / Path / Request 等类型注解，必须在头部显式导入，严禁漏导引发运行时 NameError。
- 【I/O 编码显式声明】：所有 Python 跨平台脚本在头部必须包含 sys.stdout.reconfigure(encoding="utf-8", errors="replace")，文件读写必须显式加 encoding="utf-8"。
- 【长生命周期任务全生命周期控制】：异步后台长任务必须提供全生命周期控制能力（创建、熔断取消、暂停决策），每一步操作前检查 `is_cancelled`，避免无效算力浪费。
- 【生成前质量门禁与防静默污染】：数据产物打包前必须严格校验内容完整度；若存在失败篇目，必须挂起任务弹窗交由用户自主决策（剔除坏篇/重试/终止），严禁将“抓取失败”占位符静默打包进正式电子书。
- 【本地优先与双模解耦 (Local-First Architecture)】：重度爬取与多格式转换工具采用“桌面客户端（本地 100% 运行、零云端成本、数据直接落盘）+ 云端 Web 轻量体验”双模架构，从根本上兼顾新用户极速体验与重度用户算力自由。
- 【终端双层持久化法则】：用户耗时抓取的产物索引必须在客户端本地（如 `localStorage`）建立终态镜像，即便后端重启或浏览器误刷新，历史记录与下载链接 100% 永久保留。
```
