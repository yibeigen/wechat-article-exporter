# 🧠 BlogDistiller 项目全周期核心经验与第一性原理总结 (Core Principles & Insights)

> 本文档基于 **`retrospective-distiller`** 技能规范，通过**第一性原理（First Principles）**穿透项目立项（2026-08-20）至首发正式版发布与线上实战（2026-08-29）所有排错记录的表面现象，提炼底层的本质规律与架构元原则。

## 🧭 一、 第一性原理本质剖析 (First-Principles Insights)

### 1. 跨平台富文本与文档密封性原理 (Document Engine & Asset Solidification)
- **表面现象**：抓取 HTML 转 Word/PDF 样式崩塌、图片裂开、文字占位符。
- **第一性原理剖析**：
  - 各内容平台（微信/知乎）的 HTML 包含大量私有渲染上下文（CSS Houdini、行内变量、动态计算的高度）。直接硬转必然破坏文档流。
  - 文档文件（`.docx` / `.pdf` / `.html`）本质上是**静态密封的数据容器（Sealed Data Container）**。脱离生成环境后，任何基于远程 URL 的引用都会因**网络隔离、防盗链拦截或凭证过期**而发生不可逆的“断链”。
- **底层元原则 (Meta-Rules)**：
  1. **语义降维法则**：富文本跨格式转换必须遵循 `Raw HTML -> Clean DOM -> Canonical Markdown AST -> Target Document` 的语义降维管道，先剔除噪音再按目标文档对象模型（DOM/OpenXML）重建。
  2. **二进制固化法则**：内容导出前必须将所有外链图片与多媒体数据固化为本地二进制 Buffer，并在插入时显式施加版心宽度守卫与比例锁。

---

### 2. 爬虫与第三方协议对抗第一性原理 (Crawler Protocol & Anti-Risk Invariance)
- **表面现象**：公众平台创作者后台搜号接口被封杀、微信阅读凭证过期返回 `ret: -3` 或频控 `ret: -6`。
- **第一性原理剖析**：
  - 平台的反爬本质上是**“识别异常行为特征”与“剥夺特权接口”的过程**。官方创作者后台属于中心化特权接口，封禁成本极低；而客户端点开文章所走的是**海量真实终端的日常基线流量**。
  - 防封控的核心不是“破解微信加密算法”，而是**“将程序行为完全伪装成真实用户的阅读流量”**。
- **底层元原则 (Meta-Rules)**：
  1. **去特权化法则**：放弃不可控的中心化后台接口，全面采用“本地 PAC 代理 + 真实客户端流量嗅探”技术路线。
  2. **风控透明化法则**：系统必须建立精细的风控三级诊断体系（自然过期 ➔ 0秒微信点开续期；短时限频 ➔ 指数退避；重度风控 ➔ 切换小号0秒绕过），彻底消除用户的黑盒焦虑。
  3. **数据本地沉淀法则**：历史数据一旦拉取成功，必须立即做本地缓存持久化，后续查看与导出 100% 走本地磁盘，实现 0 网络风控。

### 3. WAF 攻防对抗与特权通道对冲原理 (WAF Defense & SEO Privilege Invariance)
- **表面现象**：51CTO 在本地 Windows 可正常抓取，但部署到云服务器（Linux 数据中心 IP）后返回 567 质询拦截，检索文章数为 0。
- **第一性原理剖析**：
  - 云安全 WAF（如腾讯云 EdgeOne、Cloudflare）会依据 IP 信誉库对机房/云主机 IP 施加最高强度的防御规则（强制执行动态 JavaScript PoW 算力挑战）。Linux 无头 Chromium 因缺失真实硬件渲染上下文（WebGL、插件指纹）无法通过该挑战。
  - **内容型商业网站存在商业悖论**：网站必须依赖公网搜索引擎（Google、Baidu、Bing）收录以获取 SEO 流量，因此 WAF 防火墙底层必然对合法的搜索引擎爬虫配置了**无阻断放行通道（SEO Bypass）**。
- **底层元原则 (Meta-Rules)**：
  1. **特权通道对冲法则**：当遭遇针对机房 IP 的重度前端 JS 挑战阻断时，优先探测并对齐平台为 SEO 开放的公开抓取通道（SearchBot 协议），以极小算力代价获取完整 HTML 数据。
  2. **多通道异构容灾法则**：爬虫引擎必须设计为“秒级特权通道 ➔ 真实无头浏览器渲染”的多通道自愈兜底架构，兼顾极端穿透率与极速响应。

### 4. 异步网络 I/O 幂等与断线重试不变量 (Async I/O Idempotency & Connection Recovery)
- **表面现象**：CSDN 122 篇博文只拉取到 88 篇即中断；代码中缺失 `import asyncio` 导致静默失败。
- **第一性原理剖析**：
  - 长链路多页分页 I/O 属于分布式高频请求，边缘网关在高频访问下有概率主动断开 Keep-Alive 连接（`Server disconnected without sending a response`）。
  - 若单步请求缺失局部容灾与重试，单点网络抖动将引发整个分页管道的雪崩式中断。
- **底层元原则 (Meta-Rules)**：
  1. **单页粒度幂等重试法则**：长链路分页必须为单个页码封装 3 次自动重试与自适应退避机制，将单点网络抖动的破坏半径隔离在单页内部。
  2. **依赖强校验法则**：异步分页控制流中调用的所有模块（如 `asyncio`）必须在顶层显式声明并经过静态检查。

### 5. 解释型运行时与单点故障扩散 (Runtime Scope & Failure Blast Radius)
- **表面现象**：`background.js` 中一个未闭合的监听器或全局作用域重名变量导致整个浏览器扩展或客户端全部按钮无响应。
- **第一性原理剖析**：
  - JavaScript V8 引擎在执行前会先进行**全脚本预编译（Parse & Compile Phase）**。
  - 顶层作用域下的语法错误（`SyntaxError`）会在预编译阶段直接终止整个脚本的执行，其破坏半径是**整个执行上下文（Execution Context / Service Worker）的直接死亡**。
- **底层元原则 (Meta-Rules)**：
  1. **命名空间绝对收敛**：严禁在全局作用域下平铺声明通用函数，所有运行时方法必须统一挂载在受控命名空间（如 `window.AppCore`）下。
  2. **静态门禁法则**：任何前端与扩展代码交付前，必须无条件通过 `node --check` 自动化语法门禁。

---

### 6. 桌面应用视口锁死与边界约束 (Desktop Viewport & Layout Invariance)
- **表面现象**：最右侧出现全局双滚动条、右下角空白溢出。
- **第一性原理剖析**：
  - 桌面软件（Electron）的物理边界是绝对固定的操作系统窗口边界。
  - 当根容器允许全局滚动时，任何子组件的 margin 溢出都会导致全屏滚动条产生，破坏“原生桌面应用的质感”。
- **底层元原则 (Meta-Rules)**：
  1. **视口锁死法则**：桌面应用根节点必须强行锁死：`html, body { height: 100vh; overflow: hidden; }`。
  2. **滚动权限代理法则**：全屏滚动权限只能严格下放到具体的数据容器内部（如 `.article-table-wrapper`），禁止向外溢出。

### 7. 跨平台二进制传输与管道流式 I/O (Binary I/O & Streaming Transport)
- **表面现象**：Windows 终端 Emoji 输出报 GBK 编码错误、100MB+ 安装包上传至 GitHub 时连接中断。
- **第一性原理剖析**：
  - 操作系统终端具有区域编码依赖性（Windows 中文默认为 CP936/GBK），未声明编码的标准输出在遇到 Unicode 宽字符时必然抛出 `UnicodeEncodeError`。
  - 大体积二进制文件（>100MB）如果采用全量内存缓冲（In-Memory Buffer），会迅速耗尽堆内存并在弱网环境下发生连接超时。
- **底层元原则 (Meta-Rules)**：
  1. 跨平台脚本必须在入口处强制重构标准 I/O 为 `utf-8`。
  2. 二进制大文件分发必须采用**底层的流式分块传输（Streaming Pipeline）**或调用操作系统原生网络工具（如 `curl.exe`）。

### 8. 离线知识备份的“自包含闭包第一性原理” (Offline Archival & Self-Contained Closure Invariance)
- **表面现象**：导出的 HTML 在连网时看似图片正常，但脱机或原站删文后图片全部裂开；海外云端导出 PDF 时出现红叉/破损图片占位符。
- **第一性原理剖析**：
  - **备份（Backup）在信息论上的本质是“状态冻结与脱离上下文的独立重现”**。
  - 任何包含外部网络 URL（`http://` 或 `https://`）的所谓“备份文件”，在物理上都不是真实的数据归档，而仅仅是**脆弱且随时会失效的网络指针（Pointer）**。网络波动、DNS 劫持、防盗链拦截、原作者删帖或平台倒闭，都会使指针瞬间断裂。
  - 真正的文档备份必须构成一个**自包含闭包（Self-Contained Data Closure）**：所有非文本外部资产必须在 I/O 边界完成原子化内化，将二进制数据直接熔接进入文档宿主（HTML Base64 内联 / PDF 矢量压入 / Word 二进制流嵌入）。
- **底层元原则 (Meta-Rules)**：
  1. **零外链绝对闭包法则**：导出单文件 HTML 时，必须执行资产内嵌门禁，所有 `<img>` 必须转化为 `data:image/{mime};base64,...`，外部网络外链残留数必须归零（0 外部网络依赖）。
  2. **无网络依赖打印法则**：PDF 渲染引擎（Chromium / Playwright）接收的 DOM 必须全部基于预先转换完成的 Base64 资产，渲染过程网络请求必须归零，彻底免除海外网络延迟、跨国阻断与 403 裂图。

### 9. 中转代理通道的“信任域隔离第一性原理” (Proxy Relay & Trust Domain Isolation)
- **表面现象**：为解决海外机房访问七牛云/Cloudflare 的 403 阻断，接入了搜狗 CDN 图片代理通道，但请求搜狗代理时仍然返回 403。
- **第一性原理剖析**：
  - 反向代理与图片中转服务的防御机制，核心在于对**“发起方信任域（Caller Trust Domain）”**的鉴权与防跨站盗链检测。
  - 当通过中转通道（如搜狗 CDN）请求原站图片时，该 HTTP 请求的目标系统属于搜狗基础设施。若客户端错误地将原站专属的请求头（如 `Referer: https://www.jianshu.com/`）透传给中转服务器，中转服务器自身的 WAF 会判定该请求为非法的跨站来源并予以直接阻断。
- **底层元原则 (Meta-Rules)**：
  1. **请求头语义隔离法则**：使用第三方公用中转代理时，必须彻底剥离目标原站的私有 Referer，切换为代理平台自身的合规信任域（如 `Referer: https://pic.sogou.com/`）或空 Referer。

---

### 10. 现代移动端 SSR 骨架占位的“脱离宿主渲染上下文陷阱” (Mobile SSR Skeleton & Flow Collapse)
- **表面现象**：简书博文导出后，正文插图与紧随其后的文字段落发生严重的视觉重叠与错位撞车。
- **第一性原理剖析**：
  - 现代前端 SSR 框架（如 Nuxt/Vue）为了在移动端弱网环境下防止图片加载引发页面剧烈抖动（Layout Shift / CLS），普遍采用“外层容器 `padding-bottom: XX%` 百分比内联预占位 + 内层图片绝对定位”的骨架屏结构，同时为图片容器设置了内联固定高度（如 `max-height: 608px`）。
  - 这些结构深度依赖简书官方宿主环境的全局 CSS 运行时；一旦被爬虫提取为孤立的清洗片段，若清洗器只清除了内联样式而保留了骨架节点，该节点高度会瞬间塌陷为 0，文档流中紧随其后的文本段落直接向上漂移填补空白，形成“文字撞进图片里”的重叠灾难。
- **底层元原则 (Meta-Rules)**：
  1. **骨架屏物理剔除法则**：在 HTML 清洗阶段，必须彻底 `.decompose()` 物理剔除骨架屏占位容器（如 `.image-container-fill`），解包破坏正常文档流的内联容器（`image-container`, `image-view`）。
  2. **语义化升格法则**：图片与图说必须升格为 W3C 标准语义化标签 `<figure>` 与 `<figcaption>`，利用标准富文本排版规约保障文档流的前后间距稳定。

### 11. 高对抗平台采集的“主被动二元性”与“传输表示层语法归一化”原理 (Passive Sniffing & Presentation Layer Normalization)
- **表面现象**：自动翻页拉取历史文章频繁遭遇腾讯官方频控阻断（`ret: 200013 / freq control / -6`），且微信 4.0 API 响应中由于 JSON URL 反斜杠转义（`\/`）导致扁平正则大面积漏抓。
- **第一性原理剖析**：
  - **机器主动发包在强风控模型下的必然暴露**：无论程序对自动翻页请求如何设置随机延时，确定性的高频递增规律、单一 IP 突发连接与固定机器特征必然会被腾讯 WAF 识别并落入限频规则。
  - **网卡静默嗅探（Passive Sniffing）的天然安全特权**：网卡嗅探的本质是**“让真人作为第一请求源（Human-in-the-Loop），程序仅充当被动观测者（Observer）”**。用户在官方客户端内自然滚动的行为，拥有腾讯服务器承认的最高信任等级（合法客户端签名、真实 Cookie、真人操作时间抖动），天然具备 100% 免疫风控的特权。
  - **跨层数据解析的“语法归一化断层”**：现代 API 的多版本演进（如微信 4.0 搜一搜与新版 H5 API）会导致传输表示层（Presentation Layer）采用不同的序列化转义策略（如 `\/` 转义）。如果使用扁平正则跨层解析未经归一化清洗的字符串，本质上是在密文上跑规则，必然引发漏采。
- **底层元原则 (Meta-Rules)**：
  1. **主被动二元物理隔离法则**：高对抗平台必须将“机器主动请求（效率第一）”与“网卡被动嗅探（确定性第一）”设计为两套独立的物理工作模式，互不干扰，在极恶劣风控环境下为用户提供绝对可用的 0 风控兜底通路。
  2. **表示层语法清洗与递归 AST 探测法则**：逆向解包前必须先执行传输表示层的反转义与语法归一化（如 `\/` ➔ `/`），并在对象抽象树（AST / Object Tree）层面自顶向下递归探测文章实体，杜绝扁平正则在嵌套 JSON 中的脆弱性。
  3. **交互式智能熔断自愈法则**：当不可抗力的风控发生时，系统必须实现“熔断感知 ➔ 视觉预警 ➔ 一键流转至被动安全通道”的平滑闭环，将网络异常转化为有确定性解决方案的用户体验。

### 12. 本地优先客户端自治与“算力/分发零分叉”第一性原理 (Local-First Autonomy & Zero-Fork Distribution Invariance)
- **表面现象**：云端长耗时任务导致服务器 CPU/带宽过载、反向代理超时中断；海外机房 IP 遭遇目标平台严厉风控；传统桌面客户端每次修复反爬 bug 都必须重新打包数以百兆的安装包，迭代极其缓慢。
- **第一性原理剖析**：
  - **算力与信任域的物理本质**：数据清洗、图片下载固化与 Word/PDF 导出属于典型的**计算密集型与 I/O 密集型操作**。云端中心化集中承载这些操作会随用户规模扩大而线性消耗巨额算力，并引发单点排队；而分散在数以万计用户手中的个人 PC（CPU、SSD、家庭宽带）蕴含着无限且完全免费的并发算力。同时，用户的家庭住宅宽带 IP 在目标平台眼里是信誉最高的正常流量，登录 Cookie 仅留存于本地电脑沙盒，天然具备零泄露与零风控特权。
  - **分发管道与展示层的解耦**：传统桌面软件的致命痛点在于“代码逻辑一旦固化在安装包中，修复一行代码就需要用户重新下载整个应用”。现代 Web 的本质是**瞬时分发与零成本热更**。
  - **突破 Chromium 混合内容隔绝层 (Mixed Content Barrier)**：线上 HTTPS 页面在调用本地 HTTP `127.0.0.1` 服务时，受浏览器同源策略与混合内容阻断（Mixed Active Content）物理隔离，单纯后端 CORS 无法逾越。必须在 Electron 宿主层面解除 `webSecurity` 限制，方能打通“线上轻量展示层”与“本地自治算力层”的安全虫洞。
- **底层元原则 (Meta-Rules)**：
  1. **算力自治下沉法则**：爬虫抓取、图片缓存与多格式文档排版 100% 下沉到用户本地终端 Python 引擎中执行，产物直接直存操作系统 Downloads 目录，释放云端全部计算负载。
  2. **云端热更即刻自愈法则**：客户端首选加载线上地址（`https://doc.305758.xyz/app?client_mode=1&port=${port}`），享受免打包即时热更新；断网时通过 `did-fail-load` 自动降级至本地 Python 服务，保障离线可用。
  3. **全端零分叉共享法则 (Zero-Fork Invariance)**：严禁维护独立的多套前端分支，通过运行时特性探测（`window.electronAPI` / URL Query）动态注入 `apiBase`，实现 Web 模式与桌面模式同一套代码、全功能自治。

### 13. 异构操作系统长尾兼容的“内核双轨制”第一性原理 (Heterogeneous OS Matrix & Dual-Track Kernel Invariance)
- **表面现象**：政企事业单位机房仍有大量 Windows 7 SP1 / Windows 8.1 电脑，无法安装和运行高版本 Electron (Chromium 110+) 与 Python 3.10+，常规 Electron 客户端直接启动报错崩溃。
- **第一性原理剖析**：
  - **系统 API 的历史代际断层**：微软物理终止 Win7 支持后，Chromium 110+ 引入了大量依赖 Windows 10 `kernel32.dll` 的新系统调用，Python 3.10+ 同样移除了对旧 NT 内核的兼容补丁。
  - **“业务逻辑核心”与“平台承载外壳”的可分离性**：爬虫清洗、排版算法与前端业务属于**无系统底层依赖的纯逻辑层（Pure Logic Layer）**；而 Electron 与 Python 仅充当**执行运行时外壳（Runtime Shell）**。
- **底层元原则 (Meta-Rules)**：
  1. **内核双轨分发法则**：保持单一业务核心仓库的前提下，构建两套异构的打包分发通道：
     - **标准版 (Modern Track)**：Windows 10/11，采用 Electron 44 + Python 3.11 极致性能内核；
     - **兼容版 (Legacy Track)**：Windows 7/8.1，采用 Electron 22 + Python 3.9 稳定兼容内核。
  2. **智能自适应推荐法则**：分发入口必须通过系统 UserAgent 自动探测用户运行环境，向用户默认高亮推荐适用版本，消除老旧系统用户的认知摩擦。

```markdown
# 项目专属协作与编码规则 (AI Prompt & Coding Guidelines)

## 1. 文档导出与富文本渲染引擎
- 【语义降维管道】：跨平台富文本（HTML）转换严禁直接硬转，必须遵循 HTML -> DOM清洗 -> Markdown AST -> 目标文档 的降维重建流。
- 【资产固化原则】：所有导出格式（Word/PDF/HTML）必须真实读取本地已缓存的二进制图片（Buffer），禁止仅插入远程 URL 或文字占位符；必须读取原始尺寸并按版心等比缩放居中。
- 【HTML 绝对零外链法则】：所有以“知识备份与离线归档”为目的的 HTML 导出，必须将正文全部图片转为内嵌 Base64 Data URI（data:image/...;base64,...），严禁残留外部网络外链，确保离线断网 100% 可用。
- 【PDF 零网络打印法则】：PDF 导出前必须完成正文所有外链资源的 Base64 内联转化，提供给无头浏览器的 DOM 必须实现零网络请求，彻底消除跨国云服务器 403 阻断与破损图片占位符。
- 【移动端 SSR 骨架脱水法则】：对来自简书等 Nuxt SSR 的富文本，必须在清洗阶段彻底剔除 .image-container-fill 等高度塌陷占位节点，解包 .image-container 并升格为语义化 <figure> 标签，严禁样式冲突导致图文重叠。
- 【代理请求头信任域隔离】：使用第三方 CDN（如搜狗）作为备用代理中转拉取图片时，严禁透传目标原站的私有 Referer，必须使用中转平台合规 Referer（如 https://pic.sogou.com/）或空 Referer。
- 【Referrer 防盗链】：前端涉及微信等平台图片展示时，必须声明 <meta name="referrer" content="no-referrer">；导出场景必须走后端本地磁盘缓存通道。

## 2. 爬虫协议与反风控安全
- 【去特权化嗅探】：微信公众号历史文章抓取严禁依赖官方创作者后台草稿箱接口，统一采用“本地 PAC 代理嗅探 + 专属主页直达链接（profile_ext）”架构。
- 【WAF 特权通道】：当目标平台（如 51CTO/CDN）对云服务器机房 IP 实施严格 JS 质询（HTTP 567）时，优先配置合法的 SearchBot 特权请求头以穿透防护，并以 Playwright Stealth 作为异构兜底。
- 【长链路分页容灾】：长链路分页必须为单个页码的 HTTP 请求封装 3 次自动重试与指数退避，确保网络抖动不中断全量抓取。
- 【零风控本地沉淀】：推文与抓取结果必须第一时间落盘至 ~/.blogdistiller_data/cache/，前端切换与导出 100% 读取本地磁盘缓存，杜绝重复网络请求触发单日封禁。
- 【风控透明化】：实时计算并透传凭证 30 分钟倒计时，提供清晰的 0 秒小号切换与点开即续期指引。
- 【主被动采集双模物理隔离】：面对存在强力风控限制的目标平台，必须同时提供“机器主动解析”与“本地网卡被动嗅探”两套互不干扰的独立工作模式，并在 UI 层严格区分输入与状态。
- 【传输表示层先行清洗规范】：针对逆向拦截的 API 响应体，在执行模式匹配或提取前，必须先完成 JSON 转义符号（如 `\/`）的标准化清洗，优先采用通用对象树递归扫描，禁止单一扁平正则硬匹配。
- 【风控智能熔断与导流规范】：网络层捕获到特定的平台频控代码（如 `freq control`, `200013`, `-6`, `429`）时，严禁静默重试或仅输出原始错误字符串，必须向前端下发降级信号并弹出引导横幅。

## 3. 前端桌面布局与脚本安全
- 【单页视口锁死】：桌面客户端（Electron）根容器必须严格声明 html, body { height: 100vh; overflow: hidden; }，仅允许在数据表格区域内部开启 overflow-y: auto，杜绝全局双滚动条。
- 【弹性防挤压与安全视口法则】：在锁死高度的桌面容器中，严禁给数据表格等可伸缩容器设置过大的 `min-height`（应维持在 150-200px 保守基准），所有关键顶部交互控制面板必须显式声明 `flex-shrink: 0;`；操作引导栏设计遵循高密度流线胶囊规范，严禁纵向过度堆叠大卡片挤压核心数据视野。
- 【命名空间隔离】：禁止在前端全局作用域下随意使用 const/function 声明通用变量（如 copyText），统一通过 AppUtils 或 window.blogDistiller 注入，避免编译期 SyntaxError 导致全站白屏。
- 【语法必检规则】：每次对大型单文件 HTML/JS 及扩展 background.js 进行修改后，必须主动执行静态语法校验（node --check 或解析器验证）。

## 4. 后端服务与本地优先自治架构 (Local-First Desktop Architecture)
- 【算力 100% 下沉自治法则】：重型抓取清洗、图片压缩及 PDF/Word 排版合成必须下沉至本地 Python 进程运行，充分利用用户本机多核算力与高速磁盘 I/O，产物直存系统 Downloads 目录，杜绝云端并发排队与超时阻断。
- 【云端热更即刻自愈法则】：桌面客户端外壳默认加载线上最新前端地址，断网时自动降级到本地离线模版；功能修复与反爬适配线上秒级发布，用户免重新下载安装包即刻享用。
- 【跨协议 Mixed Content 穿透铁律】：当客户端渲染进程（HTTPS 线上地址）与本地守护进程（HTTP 本地回环 127.0.0.1）通信时，BrowserWindow 必须显式声明 `webPreferences: { webSecurity: false, allowRunningInsecureContent: true }`，彻底突破浏览器跨协议阻断。
- 【全端零分叉共享代码库】：全端共享单一 `app.html`，通过 `client_mode` 标识与 `window.electronAPI` 动态判断执行环境并挂载 `apiBase`，严禁多端分叉维护导致逻辑失步。
- 【子进程树生命周期严密管控】：本地拉起的 Python 守护进程在退出或被动关闭时，在 Windows 上必须通过 `taskkill /pid ${pid} /T /F` 强制收割子进程树，杜绝端口悬挂与孤儿进程泄露。
- 【双轨内核矩阵兼容】：针对 Windows 10/11 提供 Electron 44 + Python 3.11 极速版；针对 Windows 7/8.1 提供 Electron 22 + Python 3.9 典藏兼容版，共享单一业务仓库。
```
